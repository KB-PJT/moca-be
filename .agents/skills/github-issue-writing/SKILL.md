# GitHub 이슈 작성

## 필수 절차

1. 이슈 내용을 작성하기 전에 반드시 아래 파일을 모두 읽는다.
   - `.github/ISSUE_TEMPLATE/parent.yml`
   - `.github/ISSUE_TEMPLATE/child.yml`
   - `.github/ISSUE_TEMPLATE/config.yml`
2. 요청이 부모 이슈인지 작업 이슈인지 판단한다. 불명확하면 부모·작업 이슈 초안을 모두 제시하거나 필요한 사항만 짧게 확인한다.
3. 템플릿의 필수 필드와 순서를 그대로 사용해 내용을 작성한다. 필수 필드를 임의로 생략하거나 목록 형식으로 대체하지 않는다.
4. 부모 이슈와 연결된 작업 이슈 묶음은 하나의 브랜치와 하나의 Pull Request로 끝낼 수 있는 범위로 구성한다.
5. 부모 이슈 번호가 정해지지 않았다면 `#부모 이슈 번호`로 표시하고, 임의의 번호를 만들지 않는다.

## 출력 형식

부모 이슈는 아래 제목을 순서대로 포함한다.

```markdown
## 📌 기능 요약
## 🎯 배경 및 목적
## 📂 구현 범위
## ✅ 완료 조건
## ⚠️ 고려 사항
## 📖 참고 자료
```

작업 이슈는 아래 제목을 순서대로 포함한다.

```markdown
## 🔗 부모 이슈
## 📌 작업 요약
## 📂 작업 내용
## ✅ 완료 조건
## ⚠️ 고려 사항
## 📖 참고 자료
```

## 작성 원칙

- 제목은 `<type>(<scope>): 한글 요약` 형식을 우선 사용한다.
- 완료 조건은 확인 가능한 체크리스트로 작성한다.
- 실제로 존재하는 문서·API·경로만 참고 자료에 넣고, 불확실한 정보는 가정이라고 표시한다.
- 사용자가 "내용만" 요청하면 GitHub 생성 절차나 라벨 설명 없이 붙여 넣을 수 있는 본문만 출력한다.
